## 3. Принципы переписывания (обязательные)

Каждый новый SKILL.md обязан:

1. **Формат проекта** — YAML frontmatter как в `packs/_template/SKILL.md`:
   `name`, `description`, `argument-hint`, `user_invocable: true`, `required_tools` / `optional_tools`,
   `version`, `status: alpha`, `last_legislative_update`, `domain_owner`, `risk_level`,
   `ported_from`, `ported_at`, `adaptation_category`, `references` (НПА).
2. **Язык** — русский; англицизмы (holding, discovery, playbook, LoL, buy-side) заменять, кроме устоявшихся (matter, review — можно в скобках).
3. **Право** — только РФ (РФ + при необходимости ЕАЭС/международное). Иностранное — «за скоупом».
4. **Нормы** — конкретные статьи (кодекс, ФЗ, Пленум ВС). Не «обратись к законодательству». Проверять актуальность через `pravo.search_npa` / `pravo.get_npa_version_at_date`; нет MCP — пометка `[ред. требует проверки]`.
5. **MCP degraded mode** — skill работает без MCP, предупреждая о непроверенных редакциях.
6. **Профиль практики** — `~/.ru-legal/profiles/<pack>/PROFILE.md` (не `~/.claude/plugins/...`). Нет профиля — работать в generic-режиме, не останавливать методологические skills.
7. **Matters** — если активен `matter-management`, результаты в `~/.ru-legal/matters/<slug>/`.
8. **Секции:** Назначение / Когда запускать / Pre-flight / Workflow / Output / Что НЕ делает / Правовая основа.
9. **Attribution:** `ported_from: <autoclaw-legal>/<skill>` + абзац об адаптации. NOTICE проекта уже покрывает Anthropic CSL — расширять на новые порты.
10. **Disclaimer** — через `scripts/add_disclaimer.py` (как в CONTRIBUTING).
11. **Не дублировать:** кросс-ссылки на существующие skills (`isk-sostavlenie`, `claim-chart`, `chronology`, `contract-review`, `escalation-flagger`).
12. **Регистрация:** `packs/<pack>/pack.yaml` (список skills) + `packs/registry.json` (`skill_count`).

**Запрещено:** переносить Zwork-специфику (`PROJECT_CONTEXT`, `dxe_client.py`, legal_statute/legal_case, ydzk-разметку), US-процедуры (discovery, deposition, class action), выдуманные штрафы и сроки.

## 6. План исследования и переписывания по каждой интеграции

Формат по каждому: **исследование → замены → workflow → MCP → критерий готовности**.

Общее исследование (один раз, результаты — в `references/` или прямо в skills):

- Иерархия источников: Конституция → ФКЗ → ФЗ → указы → постановления Правительства → ведомственные акты → Пленум/Обзоры ВС → практика кассации.
- Официальные порталы: `pravo.gov.ru`, `vsrf.ru`, `kad.arbitr.ru`, `sudact.ru` (неофиц.).
- Процессуальные кодексы: АПК, ГПК, КАС, УПК — версия на дату работы skill'а.
- Опубликование: ФЗ от 14.06.1994 № 5-ФЗ; Указ Президента № 763.

### 6.1. `norm-validity-check` (из legal-norm-validity-check) — methodology

**Зачем.** Перед любой цитатой нормы — жива ли, какая редакция, действует ли на дату факта.

**Исследование.**
1. Как на pravo.gov.ru отличить: действующая ред. / утратила силу / не вступила в силу / ожидает вступления.
2. `pravo.get_npa_version_at_date` — контракт и поля.
3. Обратная сила и «переживание» закона (УК 10, ГК 4, ТК 12, КоАП 1.7).
4. Конкуренция: специальный закон vs общий; поздний акт vs ранний.
5. Что не является нормой: письмо ФНС, разъяснение, проект, судебная практика (убедить skill не называть их «законом»).

**Переписывание.** Каркас (jurisdiction/issuer/date/scope/authority) сохранить. Заменить:
- «authorized legal research tools» → `pravo.search_npa`, `pravo.get_npa`, `pravo.get_npa_version_at_date`; fallback — ручная ссылка на pravo.gov.ru.
- Output: добавить поля «Официальное опубликование», «Редакция на дату факта», «Пределы действия во времени».
- Guardrails: не считать письмо Минфина нормой; не цитировать консолидированный текст для прошлых событий без проверки ред.

**MCP:** pravo (required), web-переход на publication.pravo.gov.ru (optional).

**Готово, если:** на тесте «ст. 333 ГК, редакция на 01.01.2020 vs сегодня» skill требует версию, а не выдаёт текст по памяти; письмо ФНС классифицирует как разъяснение.

### 6.2. `research-start` — methodology

**Зачем.** План поиска до запросов, а не «я вспомнил статью».

**Исследование.** Типовой маршрут российского юриста:
1. Отрасль → кодекс (ГК/ТК/АПК/ГПК/КАС/КоАП/НК/УК).
2. Специальный ФЗ (44/223, 127, 115, 152, 135…).
3. Подзаконные и акты ЦБ/ФНС/РКН.
4. ПП ВС / Обзоры / Определения ВС по теме.
5. КАД / СОЮ практика по ключу.
6. Доктрина — только как lead, не источник.

**Переписывание.** Сохранить «leads, not authorities». Запросы писать под `pravo.search_npa` и `kad.search_cases` (ИНН, дата, суд, категория). Тег `[model knowledge — verify]` оставить. Добавить: претензионный порядок и давность — в первые вопросы плана (частые «дыры»).

**MCP:** pravo, kad (optional).

**Готово, если:** план по вопросу «взыщем неустойку» содержит ГК 330–333, 309–310, претензию (АПК 4), давность, Пленум ВС 7 от 24.03.2016 — как leads.

### 6.3. `element-extraction` (legal-element-extraction) — methodology

**Зачем.** Разобрать материалы на факты до юридической оценки.

**Исследование.**
1. Предмет доказывания: АПК 65, ГПК 56 — что обязан доказать истец по типовым требованиям.
2. Бремя доказывания и презумпции (вина причинителя — ГК 1064; добросовестность).
3. Отделить: документ / утверждение стороны / заключение эксперта / мнение юриста.

**Переписывание.** Таблицы «стороны-роли / хронология / факты по issue» оставить. Добавить колонку «Юридическое значение (предварительно)» и «Лист дела / источник». Запрет: не превращать «истец утверждает» в факт. Кросс-ссылка: дальше → `element-analysis`, `claim-chart`.

**MCP:** нет обязательных; egrul для статусов сторон (optional).

**Готово, если:** из иска и отзыва skill делает две хронологии, не склеивая, и помечает неустойку как «требование», а не «факт».

---

### 6.4. `element-analysis` — methodology (C)

**Зачем.** Есть ли состав: каждая позиция — отдельно, с пробелами.

**Исследование.** Типовые составы (как в `claim-chart`, но шире — включая защиты):
- Долг: обязательство, срок, неисполнение, размер (ГК 309, 310, 330).
- Убытки: противоправность, причинная связь, размер, вина (ГК 15, 393, 401).
- НЕО: приобретение, сбережение, без основания, за счёт (ГК 1102).
- Недействительность: по каждому основанию 166–179.
- Трудовые: законность основания + процедура + гарантии (ТК 77–84, 261, 373).
- Налоговые: событие, база, ставка, период, полномочия доначисления.

**Переписывание.** «Claim/defense/test» → «требование / возражение / состав». Никогда не писать «иск обоснован», если хотя бы один элемент `indeterminate`. Вывод — сначала gap-list. Для защит: давность, о зачёте, о несущественности нарушения, о вине кредитора (ГК 404).

**MCP:** pravo (норма-источник состава), kad (практика по элементу — optional).

**Готово, если:** по фабуле «оплатили не по реквизитам» skill не пишет «переплата = НЕО», а разводит ГК 1102 и договорный порядок, и помечает пробел «не доказано отсутствие встречного предоставления».

### 6.5. `issue-identification` (dispute-issue-identification) — methodology

**Зачем.** Список вопросов, которые реально влияют на исход.

**Исследование.**
1. Виды судопроизводства: исковое, приказное, упрощённое, особое, административное (КАС), банкротство (см. `vid-proizvodstva`).
2. Претензионный порядок: АПК 4 ч.5, ГПК (только если законом/договором).
3. Подсудность: родовая, территориальная, договорная (АПК 35–37, ГПК 28–32).
4. Давность и пресекательные сроки — как threshold.

**Переписывание.** Классификация issue: фактический / толкование / квалификация / доказательство / процесс / компетенция / способ защиты. Rank: пороговые → исходные → второстепенные. Добавить: «кто истец по природе отношения (косвенный, групповой — ГПК 244.20+)».

**MCP:** нет; kad для аналогичных споров (optional).

**Готово, если:** по «не отдаёт технику после расторжения аренды» выделяет: расторгнут ли, виндикация vs договорное, давность, обеспечительные меры, подсудность.

### 6.6. `analysis-memo` (legal-analysis-memo) — methodology (C)

**Зачем.** Полное заключение, а не чат-ответ.

**Исследование.** Структура юрзаключения, принятая в РФ:
- Вопрос (что именно спрашивают).
- Краткий ответ.
- Факты и допущения.
- Применимые нормы (со ссылкой на редакцию).
- Анализ/квалификация (почему эта норма, почему эти факты).
- Риски и альтернативы.
- Рекомендации.
- Открытые вопросы.

**Переписывание.** IRAC запрещён как ярлык. `[RESEARCH NEEDED]` оставить. Disclaimer: «черновик, не заменяет адвоката» — уже есть в DISCLAIMER.md проекта, повторить кратко. Запрет на «вероятно выиграем» без практики.

**MCP:** pravo.

**Готово, если:** меморандум по «повысили аренду на 20%» ищет ГК 424, договор, индексацию, и не выдаёт «это законно/незаконно» одним словом.

---

### 6.7. `argument-chain` — methodology

**Зачем.** Прозрачная цепочка: норма → элемент → факт → вывод.

**Исследование.** Как строится мотивировка в актах ВС: пункт нормы, фактические обстоятельства, правовая квалификация. Аналогия закона (ГК 6) — когда допустима. Пленум как толкование, а не новая норма.

**Переписывание.** Таблица шагов остаётся. Проверка на: подмену понятий (договор аренды ≠ услуга), пропуск элемента, использование отменённой нормы, «все суды так считают» по одному определению. Контраргумент — обязательный блок.

**MCP:** pravo, kad (optional).

**Готово, если:** цепочка по «взыскать убытки с директора» проходит через ГК 53.1, 44, 53, ФЗ-208/ФЗ-14, дело о причинении, вину/недобросовестность, и не прыгает в «директор всегда отвечает».

---

### 6.8. `argument-strength` — methodology

**Зачем.** Оценить чужой/свой аргумент: сильный/средний/слабый и что усилит.

**Исследование.** Типовые слабости в РФ-практике: нет претензии, пропущена давность, неверная подсудность, норма не в той редакции, практика ВС противоположная, расчет без первички, свидетель вместо документа.

**Переписывание.** Размерности (авторитет, факты, покрытие элементов, вывод, контраргументы, remedy) оставить. Без «8/10» — качественно. Сравнение с Пленумом — обязательно, если он есть.

**MCP:** pravo, kad.

**Готово, если:** по иску «только переписка в WhatsApp» skill пишет «слабо: нет первички, ходатайство об истребовании» и ссылается на допустимость электронных доказательств (АПК 78, ГПК 78, Пленум ВС 10 от 26.06.2024 — проверить).

---

### 6.9. `interpretation-argument` — methodology (C)

**Зачем.** Спор о значении текста (договора, НПА).

**Исследование.**
1. ГК 431 — буквальное, системное, предшествующие переговоры и практика (при неясности).
2. ГК 431.1 — защита слабой стороны при несправедливых условиях, Пленум ВС 49 от 25.12.2018.
3. Пленум ВС 25 от 23.06.2015 — добросовестность, 10 ГК.
4. Толкование НПА: буквальное, системное, историческое; КС и ВС.
5. Contra proferentem в РФ — ограниченно, не как в common law.

**Переписывание.** Метод «text/context/purpose/history/precedent» заменить на грамматическое → систематическое → телеологическое → практика, с весом по РФ. Цитировать только retrieved текст. Не «стереть» императивную норму целью договора.

**MCP:** pravo.

**Готово, если:** по условию «стороны договорились о штрафе 10% в день» skill не «спасает» ГК 333 через толкование, а отправляет на снижение, и отдельно — на ничтожность как злоупотребление (спорно).

---

### 6.10. `doc-summary` (legal-document-summarization) — methodology

**Зачем.** Сжать документ, не потеряв сроки, исключения, оговорки.

**Исследование.** Шаблоны выжимки для: решение/определение суда, договор, НПА, требование ФНС/РКН, акт проверки, претензия, протокол.

**Переписывание.** Сохранить структуру (тип/дата/цель/пункты/права/риски/пробелы). Для судебного акта → рекомендация `case-brief`. Для договора → `contract-review` (summary ≠ review). Обязательно: не заявлять «действующая редакция» без проверки.

**MCP:** нет.

**Готово, если:** выжимка решения сохраняет резолютивную часть дословно и срок апелляции.

---

### 6.11. `multi-doc-summary` — methodology

**Зачем.** Пакет документов дела/сделки без склейки противоречий.

**Исследование.** Типовые наборы: (1) иск+отзыв+решение+апелляция; (2) договор+ДС+приложения; (3) переписка+акты+платёжки. Приоритет: судебный акт над перепиской; ДС над старой редакцией — только если есть порядок изменения.

**Переписывание.** Хронология, матрица обязательств, реестр противоречий — оставить. Не «сливать» суммы. Источник у каждого вывода.

**MCP:** нет.

**Готово, если:** в пакете «договор 2023 + ДС 2024 + счет-оферта 2025» skill не выбирает поздний документ молча.

---

### 6.12. `research-drafting` (legal-research-drafting) — methodology

**Зачем.** Каркас черновика любого документа (не только иска).

**Исследование.** Формальные требования: иск (АПК 125–126 / ГПК 131–132), отзыв, апелляция/кассация, претензия, ходатайство, договор (существенные условия), доверенность (ГК 185, АПК 61–62 спец. полномочия).

**Переписывание.** Убрать «jurisdiction gate как блокер всегда» — для РФ юрисдикция известна; блокер — тип документа и сторона. Contract drafting: существенные условия и императив — обязательный чек. Не дублировать `isk-sostavlenie`: этот skill — маршрутизация и общие требования, иск — по паре `isk-sostavlenie` + `isk-proverka`.

**MCP:** pravo.

**Готово, если:** на «составь письмо в налоговую» даёт структуру ответа на требование (срок, реквизиты, приложения), а не иска.

---

### 6.13. `case-brief` — litigation (C)

**Зачем.** Разобрать один судебный акт: что решил, на чём, что переносимо.

**Исследование.**
1. Структура акта: вводная, описательная, мотивировочная, резолютивная (АПК 167–180, ГПК 198–214).
2. Что «holding»: вывод по вопросу + норма; мотивировка может быть шире.
3. Правовая позиция ВС (Пленум, Президиум, СКГД/СКЭС) vs казус первой инстанции.
4. Сила: Пленум > Обзор > определение ВС > кассация округа > апелляция > первая.
5. Проверка «жив ли» акт: отменён/изменён (kad, vsrf.ru).
6. Не путать отказ в передаче с согласием с мотивами.

**Переписывание.** Поля Case/Court/Posture/Facts/Issue/Holding/Reasoning/Rule — сохранить по смыслу, назвать по-русски: **Реквизиты / Суд и дата / Инстанции / Фабула / Вопрос / Вывод / Мотивы / Правовая позиция / Примечания**. Источник — только полученный текст (`kad.get_case_documents`, вложение пользователя). Нет текста — нет brief.

**MCP:** kad (required), pravo (optional).

**Готово, если:** brief определения ВС не выдаёт его за Пленум; отменённая апелляция помечается.

---

### 6.14. `evidence-evaluation` — litigation (C)

**Зачем.** Карта доказательств: что чем подтверждаем, где дыры.

**Исследование.**
1. Средства доказывания: АПК 64, ГПК 55.
2. Относимость / допустимость / достоверность / достаточность: АПК 68, 71; ГПК 59, 60, 67.
3. Электронные доказательства, скриншоты, мессенджеры (Пленум ВС 10 от 26.06.2024 — проверить актуальный номер).
4. Экспертиза: АПК 82–87, ГПК 79–87; когда без неё нельзя.
5. Истребование: АПК 66, ГПК 57 (пара к `istrebovanie-dokazatelstv`).
6. Обеспечение доказательств: АПК 72.
7. Признание факта, преюдиция (АПК 69, ГПК 61).
8. Тайна: адвокатская (ФЗ-63), коммерческая (98-ФЗ), ПДн.

**Переписывание.** «Admissibility dependencies» → конкретные основания недопустимости. Не решать «винова́т/невиновен». Inventory + матрица «issue → доказательство» + план досбора. Кросс: `chronology`, `claim-chart`, `istrebovanie-dokazatelstv`.

**MCP:** нет обязательных.

**Готово, если:** скриншот переписки помечен как «электронное доказательство, нужна идентификация участников и метаданные», а не «подтверждает договорённость».

### 6.15. `contract-desensitize` — contract-law (C)

**Зачем.** Обезличить договор/документ для шеринга.

**Исследование.**
1. 152-ФЗ: обезличивание ПДн (ст. 4, 10.1 — проверить действующую нумерацию), не имя.
2. Коммерческая тайна 98-ФЗ; адвокатская тайна ФЗ-63; банковская тайна.
3. Что реидентифицирует: ИНН, ОГРН, адрес, название проекта, сумма+дата, подписи.
4. Чем заменить DXE: python-docx / zipfile+XML — заменить текст во всех частях docx (body, headers, footnotes, comments). Mapping JSON — отдельно, не отдавать наружу.

**Переписывание.** Убрать `{python} skills/docx-revisor/scripts/dxe_client.py`. Workflow: граница раскрытия → инвентарь чувствительного → замены (одинаково) → остаточный скан → отчёт. Никогда не менять оригинал. Для md/txt — прямые замены.

**MCP:** нет. Скрипт можно положить в `packs/contract-law/skills/contract-desensitize/scripts/`.

**Готово, если:** «ООО Ромашка, ИНН 77…, Иванов И.И.» заменены согласованно во всех местах, mapping не приложен к внешней копии, остаточный скан находит «Ромашка» в колонтитуле.

### 6.16. `quick-triage` (is-this-a-problem) — risk-assessment

**Зачем.** Ответ за минуту: делаем / на review / стоп.

**Исследование.** Частые «можно ли»: отправить ПДн вендору, изменить оферту, использовать чужой знак, уволить, дать скидку агенту, оплатить из офшора, обучить ИИ на данных клиентов.

**Переписывание.** Три статуса оставить (✅ / ⚠️ / 🛑). Ловушки перевести: вендор → «что за данные и что разрешено договором/152-ФЗ»; ИИ → «на чьих данных обучаем»; увольнение → «какое основание ТК 77–81». Обязательно: если влияет давность/претензия/срок — флаг. Ответ 3–6 строк. Без файлов.

**MCP:** pravo — одна проверка нормы, если она решает вопрос.

**Готово, если:** «можно выложить переписку с клиентом в суд» → ⚠️/🛑 из-за ПДн и тайны, а не «да, суд всё равно примет».

### 6.17. `legal-risk` (legal-risk-assessment) — risk-assessment (C)

**Зачем.** Внешние регуляторные риски организации/деятельности.

**Исследование.**
1. Лицензии/СРО/уведомления: кем, когда, штраф за работу без (КоАП 14.1, УК 171).
2. ПДн: РКН, оборотные штрафы 2024+ (проверить размеры — не из памяти).
3. 115-ФЗ: банки, Росфинмониторинг (см. compliance-aml — не дублировать, кросс).
4. ФАС: картели, реклама, закупки.
5. ФНС: НДС, дробление, 54-ФЗ.
6. ЦБ: платформы, крипта (ЦФА), страховые.
7. Труд: ГИТ, суды.
8. Проверки: как читать выписку/реестр; «нет в открытом реестре» ≠ «нет записи».

**Переписывание.** Risk register: триггер, норма, факт, likelihood/impact, контроли, остаточный, эскалация. Не выдумывать суммы штрафов — либо проверено, либо «требует проверки». Кросс: `compliance-aml`, `data-protection`, `ai-governance`.

**MCP:** egrul, pravo; zakupki/efrsb — по теме.

**Готово, если:** по «запускаем маркетплейс» перечисляет: оферту, ПДн, ЗоЗПП, налоги, ответственность за товар, и не «запускайтесь, обычно ок».

### 6.18. `general-risk` — risk-assessment

**Зачем.** Риск по сделке/спору/решению — шире одной фичи.

**Переписывание.** Каркас (boundary, evidence, register, options, recommendation) оставить. Убрать корпоративный US-сленг (board, outside counsel как единственный путь). РФ: решение органа, крупная сделка/заинтересованность, одобрение, давность, исполнительное производство.

**MCP:** egrul, kad, pravo.

**Готово, если:** по «подписать ДС с новым LoL» показывает варианты, а не только «подписывай/не подписывай», и не принимает решение за клиента.

### 6.19. `feature-risk` — risk-assessment

**Зачем.** Оценка одной фичи/продукта до запуска.

**Переписывание.** Оставить фокус «2–5 рисков, меняющих решение». RU-сценарии: новые ПДн-потоки, ИИ-рекомендации, автосписание, крипта/ЦФА, маркировка рекламы, отзывы, доставка. Опции: выпустить как есть / добавить контроли / сузить / отложить. Не переносить вывод между РФ и другими странами.

**MCP:** pravo; web для свежих регуляторных кампаний (RKN/ФАС) — осторожно, только официальное.

**Готово, если:** «показываем паспорт в чате поддержки» → ПДн, доступ, логи, маскирование, а не только «это персональные данные».

## 8. Порядок работ

**Этап 0 — инфра (блокер для CI).** validate_skills.py, audit_staleness, .gitignore, путь профилей. Без этого новые skills не примет CI.

**Этап 1 — pack `methodology` (12 skills).** Они доменно-нейтральны, дают наибольший прирост. Порядок внутри: `norm-validity-check` → `research-start` → `element-extraction` → `element-analysis` → `issue-identification` → `analysis-memo` → `interpretation-argument` → `argument-chain` → `argument-strength` → `doc-summary` → `multi-doc-summary` → `research-drafting`.

**Этап 2 — litigation.** `case-brief`, `evidence-evaluation` (зависят от методологии).

**Этап 3 — contract + risk.** `contract-desensitize` (+ скрипт), pack `risk-assessment` (4 skills).

**Этап 4 — переработка старых портов** (раздел 5), начиная с `contract-review` и `claim-chart`.

**Этап 5 — docs.** README, ROADMAP, CHANGELOG, registry, NOTICE.

Каждый skill: черновик → самопроверка по чек-листу CONTRIBUTING → `validate_skills.py` → pack.yaml → registry.
