# План исследования — research-start

Перенесено из AutoClaw legal skills (`research-start`, Apache 2.0) и адаптировано
под инструменты этого проекта (`pravo-mcp`, `kad-mcp`) и российскую иерархию
источников.

## Назначение

До того как «погуглить» или «вспомнить статью», зафиксировать:

1. узкий вопрос (юрисдикция, дата, форум);
2. какие типы источников смотреть, по старшинству;
3. конкретные запросы для доступных инструментов;
4. что неизвестно и может изменить план.

Всё, что названо в плане, — **лид для проверки**, не цитата.

**Не для:** выдачи ответа, составления иска, оценки шансов.

## Входные данные

Обязательно: сам вопрос.
Опционально: дата событий, суд, отрасль, сторона (истец/ответчик/орган).

## Маршрут поиска по праву РФ

По старшинству, не перескакивая:

1. **Кодекс отрасли:** ГК, ТК, АПК, ГПК, КАС, УПК, КоАП, НК, ЖК, СК, ЗК, ГрК.
2. **Специальный ФЗ:** 44-ФЗ, 223-ФЗ, 127-ФЗ, 115-ФЗ, 152-ФЗ, 135-ФЗ, 98-ФЗ, 63-ФЗ, 123-ФЗ и т.п.
3. **Подзаконные:** постановления Правительства, акты ЦБ, ФНС, РКН, ФАС, Минтруда.
4. **Пленум ВС / Обзоры / Постановления Президиума** по теме (не по номеру дела из памяти).
5. **Практика:** `kad.search_cases` (арбитраж), СОЮ (если MCP нет — sudrf/vsrf вручную).
6. **Доктрина, комментарии** — только как наводка.

Перед шагами 1–5 обязательно: **давность** (ГК 195–208), **претензионный порядок**
(АПК 4 ч. 5), **подсудность**, **вид производства** (`litigation/vid-proizvodstva`).
Эти четыре пункта чаще меняют исход, чем «найдётся ли статья».

## Workflow

### Шаг 1 — Сузить вопрос

Запиши: что именно спрашивают, чья сторона, дата факта, форум (АС / СОЮ / КАС / внесудебно),
что уже есть в руках. Если дата или форум неизвестны и это меняет норму — пометь
`[неизвестно — уточнить]`, не выбирай «по умолчанию».

### Шаг 2 — Список источников

Для каждого уровня напиши, **что искать по теме** (институт, а не номер дела из памяти).
Пример: не «дело X», а «проценты по ст. 395 ГК при смешанном договоре».

### Шаг 3 — Запросы

Напиши реальные запросы:

- `pravo.search_npa(query="ГК РФ неустойка снижение ст. 333")`
- `kad.search_cases(text="снижение неустойки 333 ГК", date_from=..., limit=20)`

Добавь синонимы и термины: «неустойка/штраф/пеня», «убытки/упущенная выгода»,
«ненадлежащее качество/недостатки».

### Шаг 4 — Неизвестности

Список: неизвестный суд, неясен момент начала давности, нет договора, неясен вид
производства, возможна коллизия законов во времени.

## Degraded mode

**Если MCP недоступны:** план всё равно составляется. Запросы формулируются
под pravo.gov.ru / kad.arbitr.ru вручную. Ничего из памяти не помечать как
«установлено». Тег: `[model knowledge — verify]`.

## Output

```markdown
# План исследования

## Вопрос
[узкая формулировка, юрисдикция, дата, форум]

## Источники по старшинству
1. Кодекс: [что искать]
2. Специальный ФЗ: [какой, что искать]
3. Подзаконные: [орган, что искать]
4. Пленум/Обзоры: [тема, не номер]
5. Практика: [запросы для КАД/СОЮ]

## Запросы
- pravo: [...]
- kad: [...]

## Пороговые вопросы (до анализа по существу)
- давность: [что считать]
- претензия: [обязательна ли]
- подсудность/производство: [что проверить]

## Неизвестности
- [...]

## Что это НЕ
Лиды. Не цитировать в заключении до прогона через `norm-validity-check`.
```

## Что НЕ делает

- Не отвечает на вопрос.
- Не заменяет `norm-validity-check` и `analysis-memo`.
- Не ищет иностранные источники.

## Правовая основа

- АПК РФ ст. 4 (претензионный порядок), ГК РФ ст. 195–208 (давность) — как примеры
  пороговых проверок, входящих в план. Конкретные нормы — по теме вопроса.

## Связанные skills

- `methodology/norm-validity-check` — после того как нашли акт.
- `methodology/analysis-memo` — когда исследование собрано.
- `litigation/vid-proizvodstva` — выбор порядка подачи.
