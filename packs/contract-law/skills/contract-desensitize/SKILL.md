# Обезличивание документов — contract-desensitize

Полная переработка AutoClaw skill `contract-desensitize` (Apache 2.0). Убран
DXE-движок Zwork. Вместо него — локальная обработка DOCX (python-docx / XML)
и текстовых файлов. Правовая рамка — 152-ФЗ, 98-ФЗ, ФЗ-63, а не абстрактная
приватность.

## Назначение

Внешняя копия, по которой нельзя собрать реальных сторон, и отдельный mapping
для аудита/восстановления.

**Не для:** юридической оценки документа; скрытия состава преступления;
замены согласия на обработку ПДн.

## Входные данные

Обязательно: файл (docx, md, txt).
Опционально: аудитория (суд / контрагент / конференция / публикация) — определяет
глубину зачистки.

## Что заменяем

- Названия юрлиц, бренды, проекты, ИНН, ОГРН, КПП, адреса, сайты.
- ФИО, подписи, телефоны, email, паспорта, СНИЛС, счета.
- Цены, банковские реквизиты, если аудитория — публикация.
- Контекстные комбинации, реидентифицирующие после замены имён
  («единственный поставщик титана в УрФО»).

Не удаляем существенные условия — обезличивание ≠ усечение договора.

## Workflow

### Шаг 1 — Граница раскрытия

Кому пойдёт копия. Неясно — берём консервативнее и пишем допущение.

### Шаг 2 — Инвентарь чувствительного

Пройди весь документ, включая колонтитулы, сноски, примечания, свойства файла.
Составь список значений.

### Шаг 3 — Mapping и замены

JSON: `{"[ЗАКАЗЧИК]": "ООО Ромашка", "[ИНН_ЗАКАЗЧИКА]": "7700000000"}`.
Одно исходное значение — один placeholder по всему файлу.

DOCX: python-docx или zipfile + замена в `word/document.xml`, headers, footers,
footnotes, comments. Скрипт `scripts/sanitize_docx.py` рядом со skill (см. ниже).
TXT/MD: последовательные замены от длинных значений к коротким.

Никогда не менять оригинал.

### Шаг 4 — Остаточный скан

Перечитай копию независимо от списка: ФИО, домены, номера, «Ромашка» в колонтитуле,
метаданные автора DOCX. Всё найденное — в mapping, повторный sanitize **с
оригинала**.

### Шаг 5 — Выдача

Внешняя копия + короткий отчёт. Mapping остаётся внутри проекта,
`*_mapping.json` — не прикладывать к письму.

## Degraded mode

Работает без MCP. Если python-docx недоступен — zipfile+regex по XML.
Не обещай «полной анонимности», если остались изображения со штампами и подписями.

## Output

```markdown
# Отчёт об обезличивании
- Источник: [файл]
- Копия: [путь]
- Аудитория: [значение/допущение]
- Категории замен: [стороны, ИНН, ПДн, суммы...]
- Остаточный скан: [пройден / ограничения]
- Mapping: [внутренний путь, не для передачи]
- Не обработано: [картинки, метаданные, вложения]
```

## Что НЕ делает

- Не изменяет исходник.
- Не отдаёт mapping наружу.
- Не делает раскрытие законным само по себе (адвокатская тайна, КТ — отдельные вопросы).
- Не убирает ПДн из оригинала.

## Правовая основа

- 152-ФЗ — персональные данные, обезличивание.
- 98-ФЗ — коммерческая тайна.
- ФЗ-63 — адвокатская тайна.
